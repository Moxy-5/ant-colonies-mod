# Ant & Termite Colonies Mod (working title)

A Minecraft mod where ants and termites live as real colonies: they dig, build, gather food, grow, start new colonies, and fight each other. Inspired by Empires of the Undergrowth, but the player is down at ant level.

## Architecture: one colony framework, many species
- Shared systems are written once and are species-neutral: colony brain, virtual population and spawning, trails and pathfinding, nest site scoring, digging, nest growth stages, founding, foraging, defense and going home, and (later) alarm and hazard reactions.
- Each species is a **species profile**: a JSON data file in the mod's data folder that the shared systems read. I can tweak numbers there without touching code.
- A profile holds: castes (size, health, damage, speed), biomes, diggable-block tag, food tag, nest-site scoring weights, founding type (`single_queen`, `royal_pair`, `colony_fission`), nest stages and special chambers, max depth, population and real-mob caps, chase distance, and alarm/hazard responses (for example, fire: `evacuate` vs `seal_and_wait`).
- Behavior that can't be data (fungus gardens, leaf cutting, army ant bivouacs) plugs into the shared framework through hooks. Never copy a whole system to make a species version of it.
- Since the split the shared systems live in the `framework\` mod and each species in its own mod (`savanna\`, `desert\`). A species' code reaches the brain only through its colony parts (`ColonyParts` rows signed up by the species, listed in its species file) and the parts' questions, news and hooks (`ColonyQuestions`, `ColonyNews`, `ColonyHooks`), its bodies through `SpeciesBodies`; a species needing something new from the framework adds a neutral socket there, never its own name.
- Adding a species should mean: a new profile, new models, and only the special code that species truly needs.
- When building any system, check: will this work for a species we haven't added yet?

## Ant minds (the user plans truly intelligent ants and termites later)
- Keep three layers apart, so a smarter mind can replace a simpler one without touching the rest:
  1. **Mind (what to do and why):** goals today (`DigGoal`, `CarryPelletGoal`, `AntWanderGoal`), the colony brain's jobs, memory, learning and communication later.
  2. **Legs (how to get there):** `AntNavigator` (walks a route cell by cell) and `AntPathFinder` (plans routes that walk, climb walls, go over ledges and drop down holes). A mind only says "go to this cell". Species-neutral, so termites reuse it.
  3. **Body:** move control, animations, renderer.
- Never put "decide what to do" logic into the navigator or the move control, and never let a goal steer an ant with vanilla navigation or `MoveControl` directly.
- When adding behaviour, ask: could a smarter mind reuse this as a building block (perceive, remember, choose, act)?

## Species and systems (summary; every decision in full is in `docs/DESIGN.md`)
**Read the matching section of `docs/DESIGN.md` before building or changing a feature**, and record new decisions there.

- **Red harvester ant (Pogonomyrmex):** workers and a queen (no soldiers; workers sting). Plains and badlands. Eats seeds (dropped seeds, clipped short grass, grama grass later), mills them into ant bread. Deep spiral nest with a seed granary, nursery, refuse chamber; a soil hill over the entrance. Single queen founds after a nuptial flight.
- **Macrotermes (mound-building termite):** workers, minor and major soldiers, king and swelling queen, alates later. Savanna. Eats only dead plant material (dry grass, dead bush, hay, fallen branches and logs). Cathedral mound built from inside through tunnel blocks; fungus garden rooms round the royal chamber; foraging holes, runways of mud, feeding galleries under dead wood. King and queen found together.
- **Matabele ant (Megaponera analis), M8 (user, 2026-10-17):** the termites' real enemy, the first fighters: scouts, raid columns on termite feeding spots, big workers break runways and carry the dead termites home, rescue of hurt nestmates and wound care in the nest (any nestmate, no special nurses). Savanna. Colony splits to found. **Planned with the user 2026-10-18** (`docs/DESIGN.md`, "Matabele ants and the first fights"; steps in `docs/plans/m8-matabele.md`): real size spread per ant, nests in the ground, under fallen trees and in dead termite mounds (which come in M8), dig little; drawn-only ants pulled forward for 200-500 raid columns; day raids on feeding spots only; termite soldiers clamp and cut legs (lost legs show); prey eaten fast, no store; they sting a provoking player; moving house in M8, splitting in M9. Harvester ants later fight only their harvester neighbours.
- **Later species:** leafcutters, army ants.
- **Shared systems** (species-neutral, sections in `docs/DESIGN.md`): colony brain and virtual population; performance rules (real-mob cap, spawn where the player can see, no pushing); nest site scoring; founding and the colony life cycle; nest growth stages and starvation; seasons and daily schedule (Serene Seasons later); smart foraging (scouts, trails, offline timetable); digging; custom plants; hills and the ground reader; ants vs termites; alarm and hazards; player interaction.
- **Performance goal:** a mature colony holds 1,000+ insects without lag: most of it is numbers in the brain, only up to about 50 to 60 are real mobs.

## Models and animations (GeckoLib + Blockbench)
- **Size:** workers are tiny, a little smaller than a vanilla tadpole (hitbox roughly 0.3 wide × 0.2 tall). Other castes aren't sized yet; keep them proportional to the worker.
- Every mob needs: `idle`, `walk`, `attack`, `death`.
- Specials: `dig`, `carry`, `fly`, `drop_wings`, `head_bang` (termite soldiers), `pulse` (termite queen).
- Bone names are not decided yet. I'll make the first worker ant model in Blockbench first; its bone names then become the standard for every other ant and termite model, so animations can be reused. Until then, placeholder models can use any bone names.
- Walk animation speed scales with movement speed so legs never look like they're sliding.
- Until real art exists, use simple placeholder models so code is never blocked by art.

## Testing tips
- **Run game tests side by side (2026-10-16, test health plan `docs/plans/test-health.md`):** `tools/run_game_tests.sh [n]` (Git Bash) runs the tests on n servers at once (6 now, see below; the user's PC has 20 threads, 64 GB) and lists every failure at the end; `ANTCOLONIES_TESTS=antnest,away tools/run_game_tests.sh 5` for categories. Full run 2026-10-16: **109 tests, all passed, 14 minutes on 8 servers** (was 41 minutes on one). Logs per server in `run-test-shards/<i>/logs/`. A run can't be shorter than its longest test (the seed test, about 6 minutes). **On GitHub:** a push to `master`, or a commit message with `[full run]`, runs every test on 4 GitHub computers (`.github/workflows/game-tests.yml`; results on the Actions tab); it costs the account's free minutes, so not on every push.
- **The 4-box rule when a game test fails (user's plan, 2026-10-16):** (1) a real bug: fix the game **and** improve the test so it checks the right rule (user, 2026-10-16); (2) the behaviour changed on purpose: update the test; (3) the test was too strict (an exact number from a living colony): loosen it into the rule it means; (4) passes alone, fails beside others: find the leak between tests, don't just loosen the test. **Tests are kept apart** (`gametest/TestIsolation`, `docs/BUGS.md` 32): each colony rolls its own dice (`Colony.random()`, never `level.getRandom()` in colony code), a test's colonies are removed when it is done, and a check that counts a colony's insects counts its own (`TestIsolation.insectsOf`), never "everything in my box".
- **When to run which game tests (user's rule, 2026-10-13):** a full run of every game test took 20 to 30 minutes (now about 15 side by side), so do NOT run it after every change.
  - **After each change:** run only the game tests for what changed (with `ANTCOLONIES_TESTS`, see below), plus `./gradlew build`; this takes minutes. **Which ones (user's rule, 2026-10-15):** a new feature or a change to how colonies live (food, the young, the queen, the comb, eating, building) runs the category it touches **plus `away`** (life while away touches nearly everything); a simple thing (a number in a species file, a texture or model, a message, a small fix inside one goal) runs only the category it touches.
  - **Full run only:** before merging a branch into master; after changing shared systems everything uses (`AntNavigator`, `AntPathFinder`, the colony brain and its parts, digging); and once to check the 65 x 65 arenas.
  - A quick test that fails gets fixed right away. If a full run finds something the quick tests missed, add a quick test for it.
  - Every run, quick or full, uses **6 servers** (`tools/run_game_tests.sh`, the default; the user, 2026-10-22: "do 6 servers for testing and put that as default"). Drop to 4 when the user says they are busy on the PC (8 servers plus a video once ran it out of memory).
- **Test categories and no duplicate tests (user's rule, 2026-10-14):** every game test class belongs to one category (`TestFilter.CATEGORIES`): `trees` (the giant savanna trees, M7.5), `legs` (walking, climbing, termite tunnels), `antnest` (the harvester ant nest), `mound` (termite mound, cathedral, doorways, repairs), `termitefood` (foraging, garden, new holes, dead wood, runways, bare patches, mushrooms), `soldiers` (soldiers and the alarm), `colony` (founding, jobs by age, population), `away` (colonies living while the player is away, `AwayTests`), `hills` (uneven ground), `stress` (speed, only when named). Run a category by name, for example `ANTCOLONIES_TESTS=termitefood ./gradlew runGameTestServer`; after a change run the category (or categories) it touches.
  - **Before adding a new game test, check whether an existing test already builds the same scene; if so, add the new check to that test instead** (one world built, one more check). Only write a new test for a new scene. A new test class must be added to a category in `TestFilter`.
  - Never delete a check that once caught a real bug; when two tests are merged, keep every check of both.
  - Long tests with a whole working colony get a batch of their own (`batch = "..."`), so they don't get in each other's way.
  - The slim-down of 2026-10-14 took the tests from 127 to 96 (plus the stress test); the merges are listed in `docs/HISTORY.md`.
- Automatic tests Claude runs before asking the user to test:
  - `./gradlew test`: route planner on a pretend nest (part of `./gradlew build`).
  - Only some game tests (much quicker while working): set the environment variable `ANTCOLONIES_TESTS` to a comma-separated list of test class names (such as `termiteclimbingtests`) or parts of test names or category names (see above), for example `ANTCOLONIES_TESTS=termiteclimbingtests ./gradlew runGameTestServer` in Git Bash (`gametest/TestFilter`; the log then says `ONLY running n of m game tests`). Without it every test runs.
  - `./gradlew runGameTestServer`: real ants in a headless game (about 15 minutes for all 96 tests now; it was about 1 minute early on). Walks workers and the queen through a ready-made nest, and runs the whole dig (`gametest` package). Uses its own `run-test/` folder; delete `run-test/world` first for a clean run. Debug lines about routes go to `run-test/logs/debug.log`.

- **The test clock (roadmap 3a, user's decisions 2026-10-16):** a test that cares about the time of day makes its own clock, `TestClock.moving(helper, hour)` (real speed, 24,000 ticks a day) or `TestClock.still(helper, hour)`; `clock.skipTo(hour)` / `skipTo(colony, Phase.NIGHT)` only move forward; every colony in the test's arena reads it. - `/tick rate 100` speeds up time for testing growth; `/tick rate 20` sets it back to normal.
