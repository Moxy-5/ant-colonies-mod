# Testing tips (full text)

(Moved out of CLAUDE.md on 2026-11-19; CLAUDE.md keeps the rules in short.)

## Testing tips
- **Run game tests side by side (2026-10-16, test health plan `docs/plans/test-health.md`):** `tools/run_game_tests.sh [n]` (Git Bash) runs the tests on n servers at once (6 now, see below; the user's PC has 20 threads, 64 GB) and lists every failure at the end; `ANTCOLONIES_TESTS=antnest,away tools/run_game_tests.sh 5` for categories. Full run 2026-10-16: **109 tests, all passed, 14 minutes on 8 servers** (was 41 minutes on one). Logs per server in `run-test-shards/<i>/logs/`. A run can't be shorter than its longest test (the seed test, about 6 minutes). **On GitHub:** a push to `master`, or a commit message with `[full run]`, runs every test on 4 GitHub computers (`.github/workflows/game-tests.yml`; results on the Actions tab); it costs the account's free minutes, so not on every push.
- **The 4-box rule when a game test fails (user's plan, 2026-10-16):** (1) a real bug: fix the game **and** improve the test so it checks the right rule (user, 2026-10-16); (2) the behaviour changed on purpose: update the test; (3) the test was too strict (an exact number from a living colony): loosen it into the rule it means; (4) passes alone, fails beside others: find the leak between tests, don't just loosen the test. **Tests are kept apart** (`gametest/TestIsolation`, `docs/BUGS.md` 32): each colony rolls its own dice (`Colony.random()`, never `level.getRandom()` in colony code), a test's colonies are removed when it is done, and a check that counts a colony's insects counts its own (`TestIsolation.insectsOf`), never "everything in my box".
- **When to run which game tests (user's rule, 2026-10-13):** a full run of every game test took 20 to 30 minutes (now about 15 side by side), so do NOT run it after every change.
  - **After each change:** run only the game tests for what changed (with `ANTCOLONIES_TESTS`, see below), plus `./gradlew build`; this takes minutes. **Which ones (user's rule, 2026-10-15):** a new feature or a change to how colonies live (food, the young, the queen, the comb, eating, building) runs the category it touches **plus `away`** (life while away touches nearly everything); a simple thing (a number in a species file, a texture or model, a message, a small fix inside one goal) runs only the category it touches.
  - **Full run only:** before merging a branch into master; after changing shared systems everything uses (`AntNavigator`, `AntPathFinder`, the colony brain and its parts, digging); and once to check the 65 x 65 arenas.
  - A quick test that fails gets fixed right away. If a full run finds something the quick tests missed, add a quick test for it.
  - Every run, quick or full, uses **6 servers** (`tools/run_game_tests.sh`, the default; the user, 2026-10-22: "do 6 servers for testing and put that as default"). Drop to 4 when the user says they are busy on the PC (8 servers plus a video once ran it out of memory).
  - **Rule: a full run every 3 steps (the user, 2026-11-05, "could we do a full every 3 steps").** In a plan built step by step, a step runs only the categories it touches (and `away` where colony life changes), even when it changes a shared system such as `AntNavigator`; the full run comes once every 3 steps (or in the plan's own last check step, if sooner) and before any merge into `master`. This replaces "full run after changing shared systems" above for steps of a plan.
  - **Hung test servers (the user, 2026-11-05; the watchdog since 2026-11-06):** `tools/hang_watch.sh` (started by the test and soak scripts) catches a server silent 12 minutes (10 in a soak), takes a thread dump, stops it and writes `hangs.txt`; rerun what did not finish and write a new hang down in `docs/BUGS.md`. This replaces the old 31-minute check.
- **Test categories and no duplicate tests (user's rule, 2026-10-14):** every game test class belongs to one category (`TestFilter.CATEGORIES`): `trees` (the giant savanna trees, M7.5), `legs` (walking, climbing, termite tunnels), `antnest` (the harvester ant nest), `mound` (termite mound, cathedral, doorways, repairs), `termitefood` (foraging, garden, new holes, dead wood, runways, bare patches, mushrooms), `soldiers` (soldiers and the alarm), `colony` (founding, jobs by age, population), `away` (colonies living while the player is away, `AwayTests`), `hills` (uneven ground), `stress` (speed, only when named). Run a category by name, for example `ANTCOLONIES_TESTS=termitefood ./gradlew runGameTestServer`; after a change run the category (or categories) it touches.
  - **Before adding a new game test, check whether an existing test already builds the same scene; if so, add the new check to that test instead** (one world built, one more check). Only write a new test for a new scene. A new test class must be added to a category in `TestFilter`.
  - Never delete a check that once caught a real bug; when two tests are merged, keep every check of both.
  - Long tests with a whole working colony get a batch of their own (`batch = "..."`), so they don't get in each other's way.
  - The slim-down of 2026-10-14 took the tests from 127 to 96 (plus the stress test); the merges are listed in `docs/HISTORY.md`.
- Automatic tests Claude runs before asking the user to test:
  - `./gradlew test`: route planner on a pretend nest (part of `./gradlew build`).
  - **Unit test speed (test speed step 1, 2026-11-22):** the unit test classes run side by side in one test program (JUnit's own side-by-side mode, `gradle/mod-common.gradle`; a class's own tests still one after another), and the long seed loops (`MoundGrowthTest`, `TreeShapeTest`) run their seeds on all threads; a build after a savanna change went from 3 min 51 s to 50 s. (Not several test programs: they share `build/minecraft-junit` and each rewrites `config/fml.toml` as it starts, so one failed to start on the other's half-written file.) A test that cannot get faster gets `@Tag("slow")`: the everyday build leaves it out, `./gradlew :savanna:test -PslowTests` runs only those, and every full run of `tools/run_game_tests.sh` does that by itself (today only the 200-colony mound sweep). **A test class that flips a shared switch takes a lock**: `TreeShapeTest` and `TreeShapeExport` flip `TreeDraw.look` and `earlyGrowth`, so they hold `@ResourceLock("TreeDraw")` for writing and every other class that grows trees holds it for reading; a new test class that flips or reads a shared switch does the same.
  - **Game tests dealt by length (test speed step 2, 2026-11-22):** `TestFilter.keepShard` shares the tests out longest first by `tools/test-times.txt` (each test's minutes; a server's cost is the sum of its own-batch tests plus its longest default-batch test, since a batch's tests run side by side); the run script refreshes the file after every run (`tools/test_times.py`: a full run renews every time, a part run only adds new tests). Commit the file with the work. Each server's log says the minutes it expects (`[test-filter] shard i/n: ... about X min`).
  - Only some game tests (much quicker while working): set the environment variable `ANTCOLONIES_TESTS` to a comma-separated list of test class names (such as `termiteclimbingtests`) or parts of test names or category names (see above), for example `ANTCOLONIES_TESTS=termiteclimbingtests ./gradlew runGameTestServer` in Git Bash (`gametest/TestFilter`; the log then says `ONLY running n of m game tests`). Without it every test runs.
  - `./gradlew runGameTestServer`: real ants in a headless game (about 15 minutes for all 96 tests now; it was about 1 minute early on). Walks workers and the queen through a ready-made nest, and runs the whole dig (`gametest` package). Uses its own `run-test/` folder; delete `run-test/world` first for a clean run. Debug lines about routes go to `run-test/logs/debug.log`.
  - **Tests getting in each other's way (decided by the user 2026-10-13, built, NOT run yet):** a colony reaches up to 32 blocks (food radius 24, workers join a colony within 32, the alarm looks 32 out), more than the old 25-block arenas, so neighbouring tests' colonies interfered and full runs failed for no real bug. The `arena` template (`data/antcolonies/structure/arena.nbt`, used by every test) is now 65 x 16 x 65: the old arena in its north-west corner (coordinates unchanged, middle at 12, 12) plus 40 empty blocks east and south, so arenas are about 45 blocks apart. `helper.getBounds()` is the whole 65-block square. About 5 times as much ground is loaded; if the test world runs short of memory, lower the padding. After the first full run: check the time and that the neighbour failures are gone, then remove the test-only workarounds one by one (`FoodMap.setTestArea`, `Alarm.setTestArea`, `knowForTests`, the "alone" batches, `keepOutOfColonies`).
  - Until then: when a test fails only in a full run, run it on its own (or with its class) before calling it a bug. Today every full-run failure passed on its own.
- **The test clock (roadmap 3a, user's decisions 2026-10-16):** a test that cares about the time of day makes its own clock, `TestClock.moving(helper, hour)` (real speed, 24,000 ticks a day) or `TestClock.still(helper, hour)`; `clock.skipTo(hour)` / `skipTo(colony, Phase.NIGHT)` only move forward; every colony in the test's arena reads it. A test without one reads a still 7:00 (for termites that is day: a termite test that needs a night must make a clock). Rain and heat per colony: `colony.setRainForTests`, `setHeatForTests`. The old switches (`setClockForTests`, `setForagingTimeForTests`, `setSkyForTests`) are gone.
- **Never call `helper.onEachTick` inside a `runAfterDelay` (2026-11-21, mud coat test):** Minecraft's test runner then runs that timed step again and the test goes wrong every time. Register the watcher at the test's start and let it wait on a flag set later.
- Use a creative test world, `/summon`, and F3 for coordinates.
- `/tick rate 100` speeds up time for testing growth; `/tick rate 20` sets it back to normal.

## Tests left out of full runs (the user, 2026-11-23)
The user: "the test that is taking the longest, make a rule to remove it from future full sweep tests unless the change
directly affected it". A species signs a test up with `TestFilter.skipInFullRuns("<method name>")` (savanna: in
`SavannaTests.signUp`); a run with no `ANTCOLONIES_TESTS` leaves it out (as the stress tests) and says so in the log
(`[test-filter] left out of this full run`). It still runs when its category or its exact name is asked for, so a
change that touches it runs its category as usual. Signed up now: `termitesOpenTheirForagingHolesAtNightAndPlugThemByDay`
(category `termitefood`, about 12.7 minutes in its last full run, the longest). The next longest, `riverWidthIsMeasured`
(`worldgen`, about 11.9 minutes), stays in for now.
